## Annotation semantics

Check existing eligibility first. Unsupported relations/operators/Boolean schemas
produce unknown, not an impossibility proof. For supported eligible actions,
enumerate every Boolean assignment to the gathered missing coordinates, or both
Boolean replacements of the one active correction target. Preserve other heads,
coordinates, scopes and roots. Normalize through the existing relation rule.
Evaluate target resolution, final support gate (both questions resolved, payload
true), and actual final-decision availability including existing branch judgment.

The enumeration is an OVERAPPROXIMATION of admissible replies: opaque exact-payload
permits and independent references may allow only one value or reject the reply.
Do not invert hashes, call proposal/verification helpers or call either hypothetical
value actually authorized. 'possible' means a witness within the public Boolean
effect envelope CONDITIONAL ON ADMISSION; real realizability is unknown. 'ruled_out'
means no witness even in this complete envelope, for this snapshot/operation only.
No-effect/rejection is also possible and is not a successful-effect witness.
Never promise guaranteed resolution. Report unknown admission separately.
If schema/domain completeness is unsupported, return unknown for feasibility.
For a positive-witness controller below, unknown does not qualify; report that
reason explicitly. The primary cases must have supported complete envelopes.

## Controllers and bounded cases

Six controllers: current, target-resolution-oriented, final-support-gate-oriented,
each with circuit priorities or the existing exact scalar priorities. Retain
existing preflight, positive priority and lexicographic action-ID ties. Current
applies no feasibility filter. Target retains actions with a target-resolution
witness. Final retains actions with a final support-gate AND downstream nonabstaining
judgment witness in the SAME hypothetical effect. No candidate means no request.
All share the existing one-request lifetime budget and admission semantics.
Annotation is pure; memory parity is not independent annotation validation.

x2 has original shield check1 false/true and missing check2, plus missing payload.
Construct gather-only descriptors for exactly missing parts; no correction permit
or executable service. Its shield gather can add information but cannot resolve
shield. Both-offer and shield-only probes expose the target policy's sacrifice
of missing-part information; that information's later value is unmeasured.
r9 retains both correction and gather options for the target policy although each
alone leaves final abstention. r2 tests potentially sufficient gathering; r4 potential
versus failed verification; r8 resolution versus correctness; r12 potential versus
contradictory arrival; r10 already sufficient support and retained wrong prediction.

## Checks, measures and acceptance

Independently validate annotations against a separately written Boolean support
truth table across all empty/singleton/conflicting assignments to the three parts,
both equal/complement relations, gather and active-target replacement effects.
Check normalization, scoped and superseded evidence, multiple roots at a coordinate,
payload false, undetermined downstream branches, no mutation, no future access,
offer/evidence order, duplicate corroboration, real ID tie sensitivity and budget
reuse. Existing receiver duplicate/rejection/raw-evidence checks remain required.

Report per controller and case: selected action, annotation witnesses/reasons,
newly covered coordinates, coverage delta, admitted records (not independent samples),
target/all question resolutions, final decision/correct/wrong/abstain, logical
requests/service attempts/returned records or proposals/verification checks,
and remaining missing parts/conflicts/unresolved questions. No composite reward,
cost calibration or probabilities. Preparation work is separate and shared.

Acceptance means faithful operation, independent annotation checks, scalar parity,
preservation and honest accounting. Fewer answers, discarded information, failed
repairs and wrong decisions are valid findings, never grounds to retune. No expected
policy winner or improvement threshold. These known cases cannot choose a default.
